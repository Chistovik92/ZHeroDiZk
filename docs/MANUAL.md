# Руководство по установке и эксплуатации

Автор: SecretHero. Версия 0.7.7. Это пошаговое пособие для тех, кто разворачивает ZHeroDiZk и
работает с ним: сервер встреч и ретрансляции, сервер управления, веб-панель, клиенты Windows, Linux
и Android.

> **Честный статус.** Это пре-релиз. Установщики собираются в GitHub Actions и **не подписаны**
> (Windows, Linux); APK подписан ключом проекта, если выпуск собран с ним (имя файла без `-citestkey`).
> Ни один клиент автор не запускал на реальных устройствах — ждём ваших отчётов
> ([TEST-BUILDS.md](TEST-BUILDS.md)). Клиент пока **не требует** разрешений сервера управления:
> кто знает ID и постоянный пароль, тот подключится. Не используйте для важных данных и не открывайте
> в интернет без понимания рисков ([SECURITY.md](SECURITY.md)).

## 1. Что из чего состоит

| Компонент | Что делает | Когда нужен |
|---|---|---|
| **Сервер встреч и ретрансляции** (`zhd-rendezvous`, `zhd-relay`) | помогает клиентам найти друг друга и пересылает зашифрованный поток, если прямой путь закрыт | всегда, если нужны подключения |
| **Сервер управления** (`zherodizk-control`, PostgreSQL) | аккаунты, MFA, организации, устройства, группы, правила доступа, адресная книга, журнал аудита, подписанные разрешения | для учёта и управления парком |
| **Веб-панель** (`zherodizk-panel`) | управление сервером управления из браузера | вместе с сервером управления |
| **Клиент** (Windows, Linux, Android) | управляет другим устройством и/или принимает управление | на каждом устройстве |

Минимум для работы — сервер встреч и два клиента. Сервер управления и панель — для организаций.
Клиенты пока не связаны с сервером управления (этап 0.5.0, агент): устройства попадают в панель
только через API регистрации устройств (`POST /v1/devices/enroll`, подпись Ed25519,
[openapi.yaml](api/openapi.yaml)), готового диалога регистрации в клиенте ещё нет.

Где взять файлы: страница выпусков https://github.com/Chistovik92/ZHeroDiZk/releases. Рядом с файлами
лежит `SHA256SUMS`:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```

## 2. Подготовка

- **Сервер Linux** (x86_64 или aarch64) с публичным адресом или пробросом портов; от 1 ГБ ОЗУ для
  сервера встреч, ещё около 1 ГБ для сервера управления с PostgreSQL.
- **Имя в DNS** (например `rd.example.org` для встреч, `control.example.org` для управления и панели).
- **Порты** (брандмауэр сервера):

| Порт | Назначение |
|---|---|
| 21115/tcp, 21116/tcp, **21116/udp**, 21118/tcp | сервер встреч |
| 21117/tcp, 21119/tcp | ретранслятор |
| 443/tcp (и 80/tcp для Caddy) | TLS-прокси перед сервером управления и панелью |

Порт сервера управления 21114 снаружи не открывайте: он слушает только `127.0.0.1`.
- **TLS.** Сервер управления не шифрует соединение сам: без TLS пароли и токены идут открытым текстом.
  Всегда ставьте обратный прокси (Caddy, nginx) — примеры в пакетах и `packaging/`.

## 3. Сервер встреч и ретрансляции

### Установка

Debian / Ubuntu:

```bash
sudo apt install ./zherodizk-server_<версия>_amd64.deb
```

RHEL, Alma, Rocky, Fedora / ALT:

```bash
sudo dnf install ./zherodizk-server-<версия>-1.x86_64.rpm     # RHEL-семейство, Fedora
sudo rpm -i zherodizk-server-<версия>-1.x86_64.rpm            # ALT
```

Alpine, Arch и прочие: распакуйте `zherodizk-server-<версия>-linux-<arch>.tar.gz` (статические бинарники)
и запустите `zhd-rendezvous` и `zhd-relay` под отдельным пользователем; для Arch есть
`packaging/arch/PKGBUILD`. Docker: [SERVER.md](SERVER.md#docker-compose).

### Запуск

```bash
sudoedit /etc/zherodizk/server.env       # адрес ретранслятора: ZHD_RENDEZVOUS_ARGS="-r rd.example.org -k _"
sudo systemctl enable --now zhd-rendezvous zhd-relay
systemctl status zhd-rendezvous zhd-relay
sudo cat /var/lib/zherodizk/id_ed25519.pub     # открытый ключ: его вводят в клиентах
```

Закрытый ключ `/var/lib/zherodizk/id_ed25519` (права 0600) храните в секрете и включайте в резервные
копии: при его потере клиентам придётся указать новый открытый ключ.

### Проверка

```bash
sudo ss -tulpn | grep -E '2111[5-9]'          # порты слушаются
```

С другого компьютера проверьте доступность 21116/tcp и **21116/udp** (udp часто забывают открыть).

### Обновление и удаление

Новый пакет ставится поверх старого: `server.env` и ключи сохраняются. Удаление пакета останавливает
службы, но не стирает `/var/lib/zherodizk` и пользователя `zherodizk` — удалите вручную, если ключи
больше не нужны.

## 4. Сервер управления

### PostgreSQL и пакет

```bash
sudo apt install postgresql                      # нужна версия 16
sudo -u postgres psql -c "CREATE ROLE zherodizk LOGIN PASSWORD 'длинный-случайный-пароль'"
sudo -u postgres psql -c "CREATE DATABASE zherodizk OWNER zherodizk"
sudo apt install ./zherodizk-control_<версия>_amd64.deb     # rpm: dnf install / rpm -i
```

### Настройка

```bash
zherodizk-control generate-keys                  # печатает ZHD_MFA_KEY и ZHD_GRANT_KEY
sudoedit /etc/zherodizk/control.env
```

| Переменная | Значение |
|---|---|
| `ZHD_DATABASE_URL` | `postgres://zherodizk:пароль@127.0.0.1/zherodizk` |
| `ZHD_LISTEN` | `127.0.0.1:21114` (по умолчанию; снаружи не открывать) |
| `ZHD_ALLOW_REGISTRATION` | `false`: самостоятельная регистрация закрыта, первый аккаунт создаётся всегда |
| `ZHD_MFA_KEY` | ключ шифрования секретов TOTP; без него MFA недоступна; **потеря делает секреты MFA непригодными** |
| `ZHD_GRANT_KEY` | ключ подписи разрешений; без него разрешения не выдаются |
| `ZHD_AUTH_RATE_LIMIT` | запросов в минуту с адреса на анонимные точки (30; 0 — выключить) |
| `ZHD_TRUST_FORWARDED_FOR` | `true` только за доверенным прокси, который сам ставит `X-Forwarded-For` |

```bash
sudo systemctl enable --now zherodizk-control
curl http://127.0.0.1:21114/healthz          # {"status":"ok","database":"ok"}
```

### TLS

Caddy (автоматические сертификаты):

```text
control.example.org {
    reverse_proxy 127.0.0.1:21114
}
```

Готовые примеры — `/usr/share/doc/zherodizk-control/Caddyfile` и `nginx.conf`. Если панель и API на одном имени,
используйте [packaging/panel/Caddyfile](../packaging/panel/Caddyfile). После включения прокси задайте
`ZHD_TRUST_FORWARDED_FOR=true` и перезапустите службу.

### Первый аккаунт и организация

Первый аккаунт (он будет вашим администратором) создаётся в панели («Создать первый аккаунт») либо запросом:

```bash
curl -X POST https://control.example.org/v1/auth/register -H 'content-type: application/json' \
  -d '{"email":"admin@example.org","password":"не короче 12 символов"}'
```

Дальше регистрация закрыта. Остальные участники добавляются в организацию в панели (раздел
«Участники»); у добавляемого уже должен быть аккаунт, поэтому на время создания аккаунтов можно временно
поставить `ZHD_ALLOW_REGISTRATION=true`, а потом вернуть `false`.

### Docker Compose

```bash
docker build -f packaging/control/Dockerfile --build-arg BIN=bin/zherodizk-control -t zherodizk-control:local .
printf 'POSTGRES_PASSWORD=...\nZHD_MFA_KEY=...\nZHD_GRANT_KEY=...\n' > .env
docker compose -f packaging/control/docker-compose.yml up -d
```

Порт публикуется только на `127.0.0.1`.

### Резервные копии

Копируйте регулярно и проверяйте восстановление:

- база: `pg_dump -Fc zherodizk > zherodizk-$(date +%F).dump`; восстановление — `pg_restore`;
- `/etc/zherodizk/control.env` (в нём ключи), хранить отдельно от дампа и в секрете;
- закрытый ключ сервера встреч (`id_ed25519`).

Журнал аудита защищён триггерами БД от изменения и удаления записей; не отключайте их.

## 5. Веб-панель

Панель — набор статических файлов; весь обмен идёт с API сервера управления.

### Установка

Скачайте `zherodizk-panel-<версия>.tar.gz` из выпуска.

**Caddy** (проще всего):

```bash
tar -xzf zherodizk-panel-<версия>.tar.gz && cd zherodizk-panel-<версия>
sudo mkdir -p /srv/zherodizk-panel && sudo cp -a site/. /srv/zherodizk-panel/
sudo cp Caddyfile /etc/caddy/Caddyfile       # замените panel.example.org на свой адрес
sudo systemctl reload caddy
```

**nginx / Docker:** в архиве есть `default.conf.template` и `docker-compose.yml`:

```bash
tar -xzf zherodizk-panel-<версия>.tar.gz && cd zherodizk-panel-<версия>
ZHD_CONTROL_UPSTREAM=http://адрес-сервера-управления:21114 docker compose up -d     # панель на 127.0.0.1:8080
```

Перед использованием вне доверенной сети поставьте перед панелью TLS. Если API лежит на другом имени, укажите
его в `site/config.json`: `{"apiBase": "https://control.example.org"}` (тогда разрешите это имя в политике
CSP — по умолчанию панель и API на одном адресе).

### Работа

1. Откройте адрес панели, войдите (при включённой MFA потребуется код из приложения или резервный код).
2. Выберите или создайте организацию (вверху).
3. Разделы (боковое меню; видимость зависит от роли — участник, администратор, владелец):

| Раздел | Что делает | Роль |
|---|---|---|
| Обзор | число устройств, групп, действующих разрешений | участник |
| Устройства | список, отзыв устройства, одноразовый токен регистрации (24 часа, показывается один раз) | участник; токен и отзыв — администратор |
| Группы | создание групп, добавление устройств в группу и удаление из неё | участник просматривает; изменяет администратор |
| Права доступа | правило «участник — группа — возможности»; по умолчанию доступа нет ни у кого | администратор |
| Адресная книга | ваши псевдонимы устройств | участник |
| Разрешения | выданные разрешения на подключение, их отзыв | участник видит свои; администратор — все |
| Журнал аудита | события организации, экспорт в CSV и JSON | администратор |
| Участники | список, добавление (администратора добавляет только владелец) | администратор |
| Аккаунт | смена пароля, включение и отключение MFA | все |

Смена пароля завершает остальные ваши сеансы. Сеанс панели хранится в `sessionStorage` и исчезает при
закрытии вкладки; язык и тему панель запоминает в браузере.

> Разрешение живёт 60 секунд и является подписанным заявлением о праве, а не запущенным сеансом.
> Пока агент клиента его не проверяет, оно не ограничивает подключения. Панель показывает только то,
> что сообщает сервер.

### Разработка панели

```bash
cd panel && npm ci && npm run dev      # прокси на 127.0.0.1:21114
npm run build && npm test
```

## 6. Клиенты

Общее для всех клиентов:

- встроенного сервера нет. Откройте **Настройки → Сеть** (названия могут отличаться) и укажите адрес
  сервера встреч (`rd.example.org`) и его открытый ключ (раздел 3). Пока их нет, клиент показывает «не готов»;
- на устройстве, которым управляют, нужен постоянный пароль или одноразовое подтверждение; подключаясь, вводят ID
  и пароль;
- публичные STUN-серверы для определения NAT остаются (см. [SECURITY.md](SECURITY.md)).

### Windows (x64)

1. Скачайте `zherodizk-client-<версия>-windows-x64-portable.zip` и проверьте сумму.
2. Распакуйте всю папку куда угодно (например `C:\ZHeroDiZk`) и запустите `zherodizk.exe`.
3. Нужен Microsoft Visual C++ 2015–2022 (x64). SmartScreen предупредит о неподписанной программе («Подробнее →
   Выполнить в любом случае»).
4. Без службы и установщика нет управления окнами с повышенными правами (UAC) и экраном блокировки.
5. Удаление: закройте программу и удалите папку; настройки — в профиле пользователя, каталог ZHeroDiZk в `%APPDATA%`.

### Linux (X11)

```bash
sudo apt install ./zherodizk-client_<версия>_amd64.deb         # Debian/Ubuntu
sudo dnf install ./zherodizk-client-<версия>-1.x86_64.rpm      # Fedora/RHEL; ALT: rpm -i
tar -xzf zherodizk-client-<версия>-linux-x86_64.tar.gz && python3 zherodizk.py      # без установки
zherodizk --doctor          # диагностика (python3 zherodizk.py --doctor в архиве)
```

Нужен сеанс X11 (Wayland для управления не поддерживается) и `libxdo` для мыши. В Simply Linux / ALT:
`su -` и `apt-get install xdotool`, затем полностью перезапустите клиент. Настройки хранятся в
`~/.config/zherodizk/`, логи — в `~/.local/share/logs/ZHeroDiZk`; другие программы удалённого доступа не затрагиваются.

### Android

1. Скачайте APK под архитектуру телефона: `arm64-v8a` — почти все современные телефоны, `armeabi-v7a` —
   старые 32-битные, `x86_64` — эмуляторы. Не знаете — берите `arm64-v8a`.
2. Файл `…-citestkey.apk` подписан временным тестовым ключом: такой выпуск нельзя обновлять поверх
   выпуска с постоянным ключом (Android потребует удалить старое приложение).
3. Разрешите установку из этого источника (Настройки → Безопасность → «Неизвестные приложения» для браузера или
   файлового менеджера) и откройте APK. Проверка: `apksigner verify --print-certs файл.apk`; отпечаток
   SHA-256 ключа проекта публикуется в `docs/STATUS.md`.
4. Управляющий режим работает сразу. Чтобы **принимать** управление, включите службу специальных возможностей
   «ZHeroDiZk Input» (Настройки → Специальные возможности) и разрешите запись экрана при запросе; в некоторых
   оболочках нужно отключить ограничение батареи для приложения.
5. Укажите сервер встреч, как описано выше. На экране блокировки и в защищённых окнах (банковские
   приложения) ввод и показ ограничены самой системой.

Приложение не рассчитано на Google Play: правила магазина для служб специальных возможностей отдельные.

## 7. Эксплуатация

| Что | Как |
|---|---|
| Логи серверов | `journalctl -u zhd-rendezvous -u zhd-relay -u zherodizk-control -f` |
| Состояние | `systemctl status …`; `curl http://127.0.0.1:21114/healthz` |
| Обновление | поставьте новый пакет поверх; миграции БД применяются при запуске сервера управления; перед обновлением сделайте дамп |
| Смена ключа подписи разрешений | создайте новый ключ (`generate-keys`), замените `ZHD_GRANT_KEY`, перезапустите; старые разрешения истекают за минуту |
| Блокировка устройства | панель → Устройства → «Отозвать» |
| Увольнение сотрудника | отзовите его разрешения и правила доступа; учётную запись удалить нельзя (в планах), правила доступа удаляются |
| Блокировка аккаунта | после 5 неверных паролей аккаунт блокируется на 15 минут автоматически |
| Забыт пароль | смените пароль, пока есть сеанс (раздел «Аккаунт»); восстановления по почте нет |
| Потерян телефон с MFA | используйте резервный код; без него — доступ только через администратора БД |

## 8. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Клиент «не готов» | не указан сервер или ключ; доступность 21116/tcp и 21116/udp; открытый ключ скопирован целиком |
| Подключение только в локальной сети | закрыты порты ретранслятора 21117; проверьте UDP/21116 |
| Мышь не двигает (Linux) | `zherodizk --doctor`, установить `xdotool`/`libxdo`, X11 вместо Wayland |
| Панель: «Нет связи с сервером» | прокси не доходит до 21114; `curl …/healthz` на сервере |
| Панель: 429 | превышено ограничение запросов на адрес; за прокси включите `ZHD_TRUST_FORWARDED_FOR=true` |
| MFA «недоступна» (503) | не задан `ZHD_MFA_KEY` |
| Разрешения не выдаются (503) | не задан `ZHD_GRANT_KEY` |
| Регистрация закрыта | `ZHD_ALLOW_REGISTRATION=false` (первый аккаунт создаётся всегда) |
| Windows: не запускается | установите Visual C++ 2015–2022; проверьте антивирус |
| Android: «приложение не установлено» | на устройстве уже стоит APK с другим ключом: удалите его; неверная архитектура |

О проблемах сообщайте автору: https://t.me/SecretHero или https://github.com/Chistovik92/ZHeroDiZk/issues
(версия, ОС, шаги; убедитесь, что в логах нет паролей).
