# ZHeroDiZk — 0.1.0-dev.1

[![Проверки исходников](https://github.com/Chistovik92/ZHeroDiZk/actions/workflows/checks.yml/badge.svg)](https://github.com/Chistovik92/ZHeroDiZk/actions/workflows/checks.yml)

Открытый проект удалённого доступа на основе RustDesk. Начальный инженерный
пакет: диагностика Linux, получение закреплённых исходников и модуль правил
доступа. Это **не готовая замена RustDesk**, не установщик нового клиента и не
работающая серверная платформа.

Название проекта — **ZHeroDiZk**, техническое написание — `zherodizk`.
Репозиторий: https://github.com/Chistovik92/ZHeroDiZk.
Прежнее рабочее имя ZeroDisk заменено из-за совпадения с чужой программой.
История поиска и его ограничения сохранены в docs/NAME-CHECK.md.

## Что реализовано

- tools/doctor.py: диагностика Linux/X11, загрузка libxdo.so.4 / libxdo.so.3 / libxdo.so,
  проверка экспортируемых функций. Похожая libxdot.so.4 не принимается.
  Нативная библиотека проверяется в отдельном процессе с таймаутом.
- tools/bootstrap.py: загрузка клиента RustDesk 1.4.8 по полному SHA,
  проверка HEAD и наличия лицензии, отказ от перезаписи существующих каталогов.
- crates/access-policy: Rust-библиотека правил доступа без внешних зависимостей;
  запрет по умолчанию, организации, привязка разрешения к оператору/устройству,
  сроки, отзыв, согласие, постоянный доступ и пересечение разрешений.
- tools/prepare_client.py: проверка SHA/подмодулей и подготовка чистого checkout.
- tools/launch_client.py: проверка среды до запуска экспериментального клиента.
- Workflow Linux client baseline: сборка Rust/Flutter и отчёты о проверке.
- Интеграционные Python-тесты, Rust-тесты и workflow GitHub Actions.

Сборка Linux-клиента описана в [docs/CLIENT-LINUX.md](docs/CLIENT-LINUX.md).

## Быстрая проверка на Simply Linux

Скачайте исходники и откройте каталог от обычного пользователя:

```bash
git clone https://github.com/Chistovik92/ZHeroDiZk.git
cd ZHeroDiZk
```

Запустите диагностику:

```bash
python3 tools/doctor.py
```

Для отчёта JSON:

```bash
python3 tools/doctor.py --json
```

Коды выхода: 0 — проверки пройдены; 1 — предупреждение/неполная проверка;
2 — проблема. Утилита не устанавливает пакеты, не меняет права и не перезапускает
RustDesk. Не проверяет захват экрана, разрешение на подключение или реальные клики.
Она специально не называет успешную загрузку библиотеки полной готовностью.

Если в X11 отсутствует libxdo.so.3, в Simply/ALT:

```bash
su -
apt-get update
apt-get install xdotool
ldconfig -p | grep 'libxdo\.so'
exit
```

Затем полностью перезапустите RustDesk. Это прерывает удалённую сессию:
предварительно обеспечьте возможность открыть программу на удалённом компьютере.

## Разработка

Python 3.10+ и Git нужны для служебных инструментов, Rust 1.75+ — для policy crate.
Python здесь используется только для разработки/диагностики; сервер по плану — Rust.

```bash
python3 -m unittest discover -s tests -v
python3 tools/bootstrap.py --check-lock
cargo test --workspace --offline
```

Получить исходники клиента с подмодулями (требуется интернет):

```bash
python3 tools/bootstrap.py --submodules
```

Новый checkout появится в vendor/client. История и чужое авторство не переписываются.
Это исходный RustDesk без ребрендинга и интеграции правил. При сбое загрузки новый
частичный каталог остаётся для диагностики; повторный запуск в него запрещён.
Можно указать другой новый каталог через --destination.

Для сборки самого клиента нужны Flutter, Rust/C++ и платформенные библиотеки;
инструкции: https://github.com/rustdesk/rustdesk/blob/1.4.8/README.md.
Исходники клиента не включены в этот небольшой архив; bootstrap получает их отдельно.
Перед выпуском нашего бинарника полный соответствующий исходный код должен быть
доступен вместе с ним. Механизм скачивания upstream сам по себе это не заменяет.

## Ограничения текущего этапа

- Нет готового EXE, APK, панели, API, базы данных, развёрнутого hbbs/hbbr.
- Policy crate не встроен в клиент и НЕ защищает существующие сеансы RustDesk.
- Нет проверки подписи токенов, выдачи разрешений, MFA или сетевого протокола.
- Linux-клиент Rust/Flutter собран в GitHub Actions. Результаты тестов,
  проверенные коммиты и ограничения проверки — в docs/STATUS.md.
- Получение реального upstream с подмодулями проверено в CI.
  Испытания удалённого доступа на реальном Simply ещё не выполнены.

Подробности: docs/STATUS.md, docs/ARCHITECTURE.md, docs/ROADMAP.md,
docs/NAME-CHECK.md, docs/SECURITY.md и docs/HANDOFF.md.
