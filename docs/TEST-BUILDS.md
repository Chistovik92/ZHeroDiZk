# Тестовые сборки и проверка на стенде

Автор: SecretHero. Документ для тех, кто проверяет тестовые установщики. **Это не готовый продукт**:
сборки не подписаны, клиент ещё не требует разрешений сервера, а сам автор клиент на реальных
компьютерах не запускал. Именно для этого и нужна проверка.

## Что в тестовом выпуске

| Файл | Что это |
|---|---|
| `zherodizk-client-<версия>-windows-x64-portable.zip` | клиент Windows, переносимая папка (без установщика, службы и автозапуска) |
| `zherodizk-client_<версия>_amd64.deb`, `zherodizk-client-<версия>-1.x86_64.rpm`, `zherodizk-client-<версия>-linux-x86_64.tar.gz` | клиент Linux (X11) |
| `zherodizk-server_…` (deb, rpm, tar.gz; x86_64 и aarch64) | сервер встреч и ретрансляции |
| `zherodizk-control_…` (deb, rpm, tar.gz; x86_64 и aarch64) | сервер управления (нужен PostgreSQL и TLS-прокси) |
| `SHA256SUMS` | контрольные суммы всех файлов выпуска |

Проверьте сумму: `sha256sum -c SHA256SUMS`. Установщика (MSI/EXE) для Windows нет: это следующий шаг.

## Чего ждать и чего бояться

- Клиент **не требует** разрешений: любой, кто знает ID и постоянный пароль, подключится. Не ставьте на
  компьютеры с важными данными и не открывайте в интернет.
- Пока вы не укажете свой сервер, клиент покажет «не готов»: встроенных серверов нет.
- Windows: SmartScreen предупредит о неподписанной программе; нужен Microsoft Visual C++ 2015–2022
  (x64); без службы нет управления окнами с повышенными правами (UAC) и экраном блокировки.
- Linux: только X11; для мыши нужен `libxdo` (проверка: `zherodizk --doctor`).

## Минимальный стенд: сервер + два клиента

1. **Сервер встреч** (любой Linux, не за NAT или с пробросом портов): установите пакет `zherodizk-server`,
   включите службы (`systemctl enable --now zhd-rendezvous zhd-relay`), откройте порты 21115–21119/tcp и
   21116/udp. Открытый ключ сервера: `/var/lib/zherodizk/id_ed25519.pub`. Подробно — [SERVER.md](SERVER.md).
2. **Клиенты** (два компьютера): в каждом — «Настройки → Сеть → Сервер ID/ретрансляции» (названия пунктов могут отличаться): адрес сервера
   (имя или IP) и ключ из шага 1. Затем на одном компьютере посмотрите ID и пароль, на втором введите ID.
3. Сервер управления для этих проверок **не нужен**: клиенты пока с ним не связаны.

## Что проверить и о чём сообщить

Для каждого пункта запишите «работает / не работает / работает частично» и ОС с версией.

Базовые (этап 0.1.6 и 0.2.6 дорожной карты):

1. Клиент запускается; в окне и в «О программе» название ZHeroDiZk, значок — жёлтая буква Z.
2. Регистрация на вашем сервере (ID появляется, статус «готов»).
3. Подключение по прямому пути (оба в одной сети) и через ретранслятор (разные сети, прямой путь закрыт).
4. Изображение, затем управление: движение мыши, левая и правая кнопки, двойной клик, колесо,
   перетаскивание, клавиатура; русская раскладка и ввод кириллицы.
5. Несколько мониторов; смена разрешения; перезапуск клиента и компьютера.
6. Буфер обмена и передача файла в обе стороны.
7. Работа от обычного пользователя (не root, не администратор).

Только Linux / Simply (обязательные регрессии проекта): отсутствие `libxdo` при работающей клавиатуре
(`zherodizk --doctor` объясняет причину), несколько мониторов, русская раскладка, права обычного
пользователя, перезапуск.

Только Windows: запуск без прав администратора; экран блокировки; окна с повышенными правами (ожидаемо
не управляются); поведение антивируса; удаление (просто удалить папку; конфигурация — в профиле пользователя).

Безопасность (важно знать, а не «починить»): подключение с чужим ID и паролем должно работать (так сейчас
устроено); смотрите, не появляются ли обращения к посторонним серверам (трафик на `rustdesk.com` и его
поддомены быть не должен; обращения к публичным STUN-серверам известны и описаны в [SECURITY.md](SECURITY.md)).

## Как сообщать о проблемах

Пишите автору (Telegram: https://t.me/SecretHero) или в https://github.com/Chistovik92/ZHeroDiZk/issues: версия выпуска,
ОС, что делали, что ожидали, что получилось; логи клиента — Linux `~/.local/share/logs/ZHeroDiZk`,
Windows — каталог ZHeroDiZk в `%APPDATA%` (путь по коду не проверялся; проверьте, что в логах нет паролей, прежде чем присылать).
