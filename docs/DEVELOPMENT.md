# Разработка

Автор: SecretHero.

## Окружение

- Git, Python 3.10+ (только stdlib), Rust 1.75+ (CI использует 1.85.1).
- Для сборки клиента: Flutter, Rust/C++ и системные библиотеки платформы;
  Linux-сборка полностью описана workflow `client-linux.yml`.
- На Windows запускайте Python как `py -3`.

## Проверки

```bash
python3 -m unittest discover -s tests -v   # 44 теста
python3 tools/bootstrap.py --check-lock
cargo test --workspace --offline           # 17 тестов access-policy
```

Rust-тесты в CI запускаются на каждый push и PR. Локально на машине автора Rust
не установлен, поэтому локально проверены только Python-тесты.

## Правила

1. Новые файлы начинаются с `SPDX-License-Identifier: AGPL-3.0-only`.
2. Чтение и запись текстовых файлов — только с `encoding="utf-8"`; исходные файлы
   сторонних проектов правятся с сохранением окончаний строк.
3. Инструменты не перезаписывают существующие каталоги и изменённые деревья.
4. Статус в документации — только по фактической проверке. Не писать «готово»,
   пока нет зелёного запуска.
5. Не добавлять в репозиторий исполняемые файлы, секреты, ключи.
6. Название, графика и тексты — собственные; уведомления сторонних лицензий не удалять.
7. Версии — по [VERSIONING.md](VERSIONING.md); каждое изменение — запись в CHANGELOG.

## Ветки и слияние

Работа — в ветках, слияние в `main` через pull request после зелёных проверок.
Текущие правки идентичности клиента лежат в `client/linux-identity.json`:
каждая замена должна встретиться в исходнике ровно один раз, иначе подготовка
останавливается и требует ручного пересмотра.
