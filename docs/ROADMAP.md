# Этапы и критерии готовности

0. Начальная основа (этот пакет): doctor, bootstrap, policy rules, документация.
   Готовность: Python-тесты; отдельно требуется исполнить Rust-тесты в toolchain.
1. Подготовить форк клиента: собрать исходный Flutter-клиент Windows/Linux;
   импортировать с сохранением истории; тест прямого и relay соединения.
   Добавить libxdo в Linux package dependencies и диагностику в GUI/агент.
2. Сервер управления: локальные аккаунты, Argon2id, MFA, PostgreSQL,
   регистрация ключей устройств, ACL, аудит, документированный API.
   Никаких реальных удалённых прав до интеграции криптографической проверки.
3. Вертикальный управляемый сеанс: выдача/проверка разрешения, согласие,
   обязательные policy checks на агенте и запрет обходных путей.
   Отказ по чужой организации, отозванному/просроченному разрешению и replay.
4. Панель: устройства, группы, адресная книга, права, активные сеансы,
   журнал и прекращение сеанса. Реальные данные API, без фиктивных статусов.
5. Эксплуатация: установка, Compose, резервирование и проверка restore,
   подписанные обновления, миграции с планом восстановления.
6. Платформы и масштаб: macOS, Android, Wayland, несколько relay, корпоративный вход.

Windows-клиент и Linux-сервер — первый публичный целевой контур. Simply Linux
включить в обязательные регрессии: отсутствие libxdo при работающей клавиатуре;
несколько мониторов; русская раскладка; права обычного пользователя; перезапуск.
