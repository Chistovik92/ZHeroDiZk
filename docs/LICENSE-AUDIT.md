# Аудит лицензии подмодуля hbb_common (пункт 0.1.4)

Автор: SecretHero. Дата проверки: 3 октября 2026. Это инженерный разбор по
публичным данным, **не юридическая консультация**.

## Вопрос

Закреплённый исходный клиент (тег 1.4.8) подключает `libs/hbb_common` как
подмодуль на ревизии `387603f47cbb15c0d3dc3d67ae3396d3eb707daf`. Отдельный
репозиторий этого подмодуля не содержит файла лицензии. Можно ли считать код
распространяемым на условиях AGPL-3.0 вместе с остальным клиентом?

## Установленные факты

Проверено через GitHub API:

| Факт | Результат |
|---|---|
| Корень репозитория подмодуля на закреплённой ревизии | `.gitignore`, `Cargo.toml`, `build.rs`, `examples`, `protos`, `src` — файла LICENSE/LICENCE нет |
| Поле `license` в `Cargo.toml` подмодуля | отсутствует |
| Определение лицензии GitHub для репозитория подмодуля | `null` |
| `libs/hbb_common` в основном репозитории на тегах 1.1.9 и 1.2.0 | **обычный каталог внутри дерева**, то есть распространялся как часть репозитория с файлом `LICENCE` |
| `libs/hbb_common` на теге 1.4.8 | подмодуль |
| `LICENCE` основного репозитория на теге 1.4.8 | GNU AGPL v3 |

## Вывод

1. Код `hbb_common` изначально публиковался внутри репозитория под AGPL-3.0.
   Позднее он был вынесен в отдельный репозиторий без копирования файла лицензии.
   Это выглядит как пропуск в метаданных, а не как другая лицензия: явных иных
   условий нигде не найдено.
2. Отдельного явного разрешения в самом подмодуле нет, поэтому утверждать
   «лицензия подтверждена» нельзя. Остаточный риск: правообладатель формально
   не подтвердил условия для отдельного репозитория.
3. Рабочее решение проекта: клиент, включающий этот код, распространяется как
   единое произведение под AGPL-3.0, с сохранением всех уведомлений об авторах
   (в том числе `authors` из `Cargo.toml` подмодуля) и со ссылкой на закреплённую
   ревизию. Код подмодуля **не переименовывается в наш** и не перелицензируется.
4. Перед релизом 1.0.0 (пункт «все лицензионные вопросы закрыты» дорожной карты)
   желательно получить подтверждение от правообладателя (запрос в их репозиторий
   с просьбой добавить файл лицензии) и юридическую проверку. Обращение
   публичное и от имени автора проекта; без его решения оно не отправляется.

## Что остаётся открытым

- Лицензии транзитивных зависимостей Rust и Dart — проверяются отчётом из
  пункта 0.1.5 (`tools/sbom.py`), полного юридического разбора ещё нет.
- Кодеки и библиотеки, собираемые через vcpkg, не разобраны.
- Графика и шрифты исходного клиента: проверка и замена — этап 0.2.0.
